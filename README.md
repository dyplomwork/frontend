# Симулятор мініігор — фронтенд

Клієнтська частина вебплатформи «Симулятор мініігор» — односторінковий застосунок (SPA) на
**Vue 3**, що надає інтерфейс для казино-подібних мініігор на віртуальній валюті, ігрової
економіки (кейси, інвентар, аукціон), битв у реальному часі та адміністративної панелі.

Застосунок працює у зв'язці з [бекендом](../dyplom_work_backend) (мікросервіси Node.js):
усі ставки, баланс і результати обчислюються на сервері, клієнт лише відображає стан.

## Технології

- **Vue 3** (Composition API) + **TypeScript**
- **Vite 6** — збірка та dev-сервер
- **vite-ssg** — статична генерація сторінок (SSG) для продакшену
- **Pinia** — керування станом
- **Vue Router** — маршрутизація
- **vue-i18n** — інтернаціоналізація (українська / англійська)
- **Vitest** + **@vitest/coverage-v8** — модульні тести
- **Playwright** — наскрізні (E2E) тести
- **MSW** — моки HTTP-запитів у тестах
- **ESLint** + **Prettier** — лінтинг і форматування

## Можливості

- **Мініігри:** Dice, Roulette, Mines, Plinko, відкриття кейсів.
- **Coin Flip** — PvP-битви з оновленням стану в реальному часі (Server-Sent Events).
- **Економіка:** інвентар предметів різної рідкості, аукціон між гравцями, продаж вендору.
- **Клікер** — пасивне заробляння коінів і конвертація у валюту платформи.
- **Поповнення балансу** через **Google Pay** (тестове середовище).
- **Профіль** зі статистикою та досягненнями.
- **Автентифікація** за нікнеймом або через обліковий запис **Google**.
- **Адмінпанель:** користувачі (пошук, фільтри, пагінація), бани, аналітика ігор і дропів,
  донати й дохід, журнал дій.
- **Двомовний інтерфейс** (UA/EN) та адаптивна верстка.

## Структура

```
dyplom_work_front/
├── src/
│   ├── views/            # сторінки (за маршрутами)
│   ├── components/        # спільні компоненти
│   ├── stores/            # сховища Pinia (auth, баланс, ігри…)
│   ├── router/            # опис маршрутів
│   ├── locales/           # переклади ua.ts / en.ts
│   ├── core/config/env.ts # визначення базового URL API
│   ├── data/              # статичні дані (напр. кейси)
│   ├── styles/            # CSS
│   └── types.ts           # спільні типи
├── public/                # статика (зокрема public/icon/*.png)
├── scripts/               # генерація sitemap при збірці
└── vite.config.ts
```

Сторінки (`src/views`): Home, Login, Register, Profile, Dice, Roulette, Mines, Plinko,
Cases / CaseDetail, CoinFlipLobby / CoinFlipBattle, Clicker, Inventory, Auction, Donate, Admin.

## Початок роботи

Потрібен **Node.js 18+**.

```bash
npm install        # встановити залежності
npm run dev        # dev-сервер (http://localhost:5173)
```

Для локальної розробки створіть файл **`.env.local`** і вкажіть адресу запущеного бекенду:

```bash
VITE_API_BASE_URL=http://localhost
```

(Бекенд має бути піднятий — див. [README бекенду](../dyplom_work_backend/README.md).)

## Конфігурація (змінні середовища)

Усі змінні з префіксом `VITE_` Vite вбудовує у збірку. Базовий URL API визначається в
`src/core/config/env.ts` за таким пріоритетом: режим моків → явний `VITE_API_BASE_URL` →
продакшен (той самий домен через rewrites Vercel) → `http://localhost` у dev.

| Змінна                  | Призначення                                                       |
|-------------------------|-------------------------------------------------------------------|
| `VITE_API_BASE_URL`     | базовий URL API (у dev — `http://localhost`; у проді не задається — той самий домен) |
| `VITE_GOOGLE_CLIENT_ID` | Client ID для входу через Google                                 |
| `VITE_MOCK_API`         | `1`/`true` — увімкнути моки MSW (без реального бекенду)           |
| `VITE_SITE_URL`         | повна адреса сайту для SEO/sitemap                               |

## Доступні скрипти

| `npm run dev`       | dev-сервер Vite                                          |

| `npm run preview`   | локальний перегляд зібраного застосунку                 |

| `npm run check`     | повна перевірка: typecheck + lint + build               |

## Іконки

Кастомні іконки лежать у `public/icon/` і підключаються через `<img src="/icon/НАЗВА.png">`
(папка `public/` віддається з кореня сайту).

## Деплой

Фронтенд розгортається на **Vercel** як статичний сайт (SSG). У продакшені `VITE_API_BASE_URL`
не задається, тож запити `/api/v1/...` йдуть на той самий домен і перенаправляються
(rewrites у `vercel.json`) на бекенд (Railway) — SPA і API працюють під одним походженням,
без проблем із CORS.

## Тестування

```bash
npm test             # модульні тести (Vitest + MSW)
npm run check        # типи + лінт + збірка перед публікацією
```

E2E-сценарії на Playwright перевіряють ключові шляхи: реєстрацію, ігри, економіку предметів
та битви в реальному часі.
